# 周/月度支出报表与新流程数据收集

## 名称与口径

- 原付款申请周报、月报的在线快照、Excel 和 PDF 文件名统一显示为 **周度支出报表 / 月度支出报表**。
- 消息卡片及文本通知统一显示为 **支出项目周报 / 支出项目月报**；数据范围和汇总口径不变。
- 付款申请日报保留原名称和原 FNS/NBHH 范围。
- 周/月报默认汇总来源应用中启用的付款申请、员工薪资发放申请A、日常报销单据；页面和 Excel 明确列出覆盖流程及每类申请数、申请金额。
- 按 **申请公司** 映射归属，不按来源应用公司、申请人或收款人猜测；其他映射公司可单独生成周/月报。
- 所有总额都是 **支出申请额**。审批完成、同意或已填入账日期都不能证明实际已支付；本次没有把它们转换为已付款金额。
- 按申请发起时间归周/月。期望付款日期、入账时间、费用发生日期保留用于核对，不从事由文本猜工资所属月份。

## Admin配置

在「钉钉审批模板」为来源应用配置以下两项：

1. 模板名称 **员工薪资发放申请A**，Code如上，金额组件名 **付款总额**。
2. 模板名称 **日常报销单据**，Code如上，金额组件名 **报销金额（元）**。

与付款申请使用同一来源应用、同一申请公司映射和同一审批实例表，不创建另一套账号配置。业务记录通过公司+实例ID幂等保存。

来源字段暂不读取/导出薪资附件内个人工资、银行卡或原始附件链接。报销JSON保留金额、原因、行号、可用日期等规范化明细，附件文件不进入支出报表。

新流程的月度收集：

~~~sh
python manage.py sync_expense_approvals --app-id 1 --period 2026-10 --dry-run
python manage.py sync_expense_approvals --app-id 1 --period 2026-10
~~~

默认遇到未映射公司或明细合计不一致时，整批预检失败，尚未写入任何实例。明确希望给新的申请公司建立独立组织时，可加 --create-missing；组织代码使用与原付款修复脚本相同的 DT-名称哈希，不混入 FNS。

现有 sync_running_approvals 同时支持新流程，刷新近期新增审批和已保存的运行中实例，不改变既有自动推送选中的公司和群。

## 推送与快照

- 继续复用现有 send_payment_report week / month 和群配置的周/月周期。
- 未显式 --process-code 时包含启用的支出来源；显式指定流程Code时可生成单来源报告，并在正文说明覆盖范围。
- 多来源快照身份用流程Code集合的哈希，旧单付款申请快照继续可访问，不覆盖历史冻结数据。
- 未新增或自动启用群、没有自动授权新的申请公司到既有推送群。
- 当前签名公开快照链接30天有效，链接持有者可访问，请仅在授权群内发送。

## 日期排序

- 付款/支出查询和网页、PDF、Excel明细跨收款人按发起日期降序，同日有发起时间时按时间降序。
- 原日报账簿和邮件附件的销售/采购明细按日期降序。
- ERP经营分析中的日期明细和月份表按日期降序；趋势时间轴仍按自然时间递增，金额排行仍按对应金额排序，不改计算数据。
- 旧付款PDF缓存版本已递增，下载不会继续命中升序旧PDF。

## 日常报销字段映射修正（2026-11-04）

日常报销的收款人使用套件表头「归属人」人员显示名（优先 extValue.name），不取申请人、收款账户或内部人员 ID。付款事由使用「报销明细 → 费用说明」，多条明细按原顺序以分号连接且不截断。归属人缺失显示「归属人未填写」。金额、审批笔数、申请公司、归期和日期降序不变；付款申请和薪资的映射不变。旧规范化记录可从已保存 raw 中读取归属人，无需重拉钉钉。更新已生成快照时只重分收款人/费用说明，保持快照ID、签名访问地址及冻结金额/状态不变。

## 申请人姓名补齐（2026-11-09）

- 钉钉审批详情接口只返回发起人 `originator_userid`，不返回姓名；旧同步把空字符串写进 `originator_name`，导致网页、Excel、PDF 的「申请人」列全空。
- 同步时按 userid 调 `topapi/v2/user/get` 取通讯录姓名并缓存；接口失败或权限不足时回退审批标题前缀「XXX提交的…」，两者都取不到才留空，不阻断同步。
- 重复同步不会把已回填的姓名清空。
- 历史数据用 `backfill_originator_names` 回填：默认 dry-run，`--apply` 才写库；只改 `originator_name`，不触发 `auto_now`。
- 该命令同时刷新已有支出报表快照中为空的 `originator`：写库前对比申请人以外的整份 JSON，金额、笔数、状态、排序必须完全一致；只刷新 `generated_at` 以失效旧 PDF 缓存，快照 ID 和签名链接不变。
- 已发送到群里的历史 Excel/PDF 不会自动变化；需要时重建快照后重发。
