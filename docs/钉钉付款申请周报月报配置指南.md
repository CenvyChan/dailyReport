# 钉钉付款申请周报/月报配置指南

## 功能说明

定期汇总钉钉付款申请审批数据，生成 Excel 报表并推送到钉钉群，包括：
- **周报**：统计上周（周一至周日）的付款申请
- **月报**：统计上月（1日至月末）的付款申请

## 前置条件

### 1. 钉钉应用配置（DingtalkApp）

在 Django Admin 中配置钉钉应用，需要以下字段：

| 字段 | 说明 | 获取方式 |
|------|------|----------|
| app_key | 应用的 AppKey | 钉钉开放平台 → 应用管理 |
| app_secret | 应用的 AppSecret | 钉钉开放平台 → 应用管理 |
| corp_id | 企业 CorpId | 钉钉开放平台 → 企业信息 |
| agent_id | 应用的 AgentId | 钉钉开放平台 → 应用管理 |
| **robot_code** | **群机器人 Code** | **见下文获取步骤** |

### 2. 获取群机器人 robotCode

#### 方法一：通过钉钉开放平台

1. 登录 [钉钉开放平台](https://open-dev.dingtalk.com)
2. 进入你的应用 → 机器人与消息 → 群机器人
3. 创建或查看现有群机器人，复制 `robotCode`

#### 方法二：通过 API 查询

```bash
# 在服务器上执行
docker exec daily-report-web python manage.py shell
```

```python
from integrations.services.dingtalk_client import DingtalkClient
from integrations.models import DingtalkApp

# 获取钉钉应用
app = DingtalkApp.objects.first()
client = DingtalkClient(app)

# 查询应用下的所有机器人
result = client.get('/v1.0/robot/orgRobots')
for robot in result.get('result', {}).get('list', []):
    print(f"机器人名称: {robot['name']}")
    print(f"robotCode: {robot['robotCode']}")
    print("---")
```

### 3. 获取群 openConversationId

```python
# 在 Django shell 中执行
from integrations.services.dingtalk_client import DingtalkClient
from integrations.models import DingtalkApp

app = DingtalkApp.objects.first()
client = DingtalkClient(app)

# 机器人加入的所有群
result = client.post('/v1.0/robot/groupsOfRobot', {
    'robotCode': app.robot_code,  # 使用上面获取的 robotCode
    'maxResults': 50,
})

for group in result.get('result', {}).get('groupInfos', []):
    print(f"群名称: {group['name']}")
    print(f"openConversationId: {group['openConversationId']}")
    print("---")
```

## 使用命令

### 测试周报生成（dry-run）

```bash
docker exec daily-report-web python manage.py send_payment_report week \
  --dry-run \
  --output-dir /app/data
```

### 测试月报生成（dry-run）

```bash
docker exec daily-report-web python manage.py send_payment_report month \
  --dry-run \
  --output-dir /app/data
```

### 发送周报到钉钉群

```bash
docker exec daily-report-web python manage.py send_payment_report week \
  --group-id "cidXXXXXXXX"
```

参数说明：
- `--group-id`：钉钉群的 openConversationId（必需）
- `--company`：公司代码，默认发送所有启用钉钉的公司
- `--process-code`：审批模板 Code，默认使用配置中的付款申请模板
- `--base-date`：基准日期（YYYY-MM-DD），用于测试历史数据
- `--output-dir`：Excel 输出目录，默认为临时目录
- `--dry-run`：仅生成 Excel 不发送
- `--mention`：要@的用户ID列表（空格分隔）

### 定时任务配置

在服务器上配置 cron（或使用 scheduler sidecar）：

```bash
# 每周一早上 9:00 发送周报
0 9 * * 1 docker exec daily-report-web python manage.py send_payment_report week --group-id "cidXXXXXXXX" >> /var/log/payment-report.log 2>&1

# 每月1日早上 9:00 发送月报
0 9 1 * * docker exec daily-report-web python manage.py send_payment_report month --group-id "cidXXXXXXXX" >> /var/log/payment-report.log 2>&1
```

## Excel 报表结构

生成的 Excel 包含 4 个工作表：

### 1. 汇总统计
- 统计周期、起始/结束日期
- 总申请数、总金额
- 各状态分布（已完成、进行中、已终止、新建）

### 2. 按收款人汇总
- 收款人名称
- 申请数、总金额
- 各状态明细（已完成、进行中、已终止）

### 3. 详细清单
- 申请日期、收款人、付款金额
- 付款事由、期望付款日期
- 状态、申请人、审批标题、审批实例ID

### 4. 原始数据
- 完整的 JSON 格式数据
- 便于二次处理和数据分析

## 故障排查

### 错误：robot 不存在

**原因**：未配置 `robot_code` 或配置错误

**解决**：
1. 检查 `DingtalkApp.robot_code` 是否已配置
2. 使用上述方法获取正确的 `robotCode`
3. 确保机器人已加入目标群

### 错误：找不到付款申请

**原因**：
- 审批模板未配置
- 时间范围内无数据
- 数据未同步

**解决**：
1. 运行 `sync_payment_approvals` 同步数据
2. 检查 `DingtalkProcessConfig` 配置
3. 使用 `--base-date` 测试历史数据

### 时区警告

```
RuntimeWarning: DateTimeField received a naive datetime
```

**影响**：不影响功能，仅为警告

**原因**：日期范围计算使用了 naive datetime
