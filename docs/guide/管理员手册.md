# FINOSSReportSystem · 管理员手册

面向系统管理员与运维。业务操作说明见同目录的 `用户使用指南.html`。

- **访问地址**：http://172.16.77.80:8001/
- **后台地址**：http://172.16.77.80:8001/admin/
- **部署主机**：`mesdevserver`（172.16.77.80，用户 `mesdev`）
- **部署目录**：`~/deploy/daily-report`

---

## 1. 系统概览

| 项 | 内容 |
|---|---|
| 框架 | Django 5.1 + waitress，内网 HTTP |
| 数据库 | SQLite（WAL 模式），文件在 `data/daily_report.sqlite3` |
| 容器 | `daily-report-web`（对外 8001→8000）、`daily-report-mailer`（定时发信） |
| 时区 | Asia/Shanghai（容器内已固定，与发送时间判断相关） |

### 多公司模型

当前已配置 **飞诺斯电子科技有限公司（FNS）** 和 **宁波汇慧有限公司（NBHH）**。隔离边界在数据，不在身份：

- **按公司隔离**：客户、供应商、月度汇率、销售日报、采购日报。
- **两家共用**：用户账号、密码、角色（销售/采购/管理员/报表查看者）。
- 谁能进哪家公司，由 **用户公司授权**（`CompanyMembership`）决定。

因此：同名客户可以在两家各存一份；同一月份可以维护两套不同汇率；一个账号可以同时授权两家，登录时选择进哪家。

## 2. 首次上线检查清单

1. 两个容器都是 `Up`：`ssh mesdevserver "docker ps --filter name=daily-report"`
2. 登录页可访问：`curl -o /dev/null -w "%{http_code}\n" http://172.16.77.80:8001/accounts/login/` 应返回 `200`
3. 已创建管理员，且已授权公司（见 §3）
4. 公司名称改成真实公司名（后台「基础管理 → 公司」）
5. 维护当月汇率（两家公司分别维护）
6. 配置邮件发信参数并试发（见 §6）

## 3. 用户与权限管理

### 角色说明

| 角色 | 能做什么 |
|---|---|
| 管理员 administrator | 维护用户、公司授权、汇率、基础资料，查看全部销售采购数据，执行导入 |
| 销售 sales | 填写并查看本人负责客户的销售日报 |
| 采购 purchase | 填写并查看本人负责供应商的采购日报 |
| 报表查看者 report_viewer | 只看销售和采购分析报表，不能录入 |

### 新建用户

前台「用户 → 新增用户」，填用户名、姓名、**角色（可多选）**、**可进入的公司（可多选）**、初始密码。

初始密码要求：**至少 8 位、不能是纯数字、不能是常见弱密码**（如 password、12345678）。重置密码同样受此限制。

角色多选用于兼岗，例如同时管销售和采购的人可同时勾「销售」「采购」。用户首次登录会被强制**填写本人邮箱并修改密码**，邮箱用于日报推送，之后可在「个人设置」自行修改。

也可批量导入：「用户 → 导入用户」，模板列为 用户名、姓名、角色、初始密码。**导入的账号只会被授予当前登录公司的权限**，要进另一家需另外补授权。

### 调整公司授权

后台 `/admin/` →「基础管理 → 用户公司授权」增删记录。删除某人对某公司的授权后，他登录时就选不到那家公司了；已经登录的会话在下次请求时会回退到其它仍被授权的公司。

### 重置密码

前台「用户」列表 → 对应行「重置密码」。重置后该用户下次登录必须自行改密。

### 员工离职（停用账号）

前台「用户」列表 → 对应行「停用」。停用后该账号无法登录，但**历史日报全部保留**，报表里仍能看到他的名字。停用的行会灰显，一眼能看出谁已离职。

不要删除账号：日报的负责人字段是 PROTECT 外键，有数据的账号删不掉；即使删得掉，历史归属人也会丢。

需要复职时点同一行的「启用」即可，角色和公司授权都还在。

两种情况按钮不会出现：**自己的账号**，以及**最后一个启用的管理员**（停掉就没人能管系统了，只能去命令行救）。

### 客户/供应商归属

销售只能选到**分配给自己**的客户。在后台「销售客户归属」/「采购供应商归属」维护。注意客户本身属于某家公司，把飞诺斯的客户分给某人，他登录宁波汇慧时依然看不到。

> ⚠️ **权限边界提醒**：`administrator` 目前是**全局可信角色**。只授权一家公司的管理员，仍然可以新建一个有另一家公司权限的账号、或重置对方用户的密码，从而间接看到另一家的数据。如果需要「公司级受限管理员」，需要额外开发。请谨慎分配管理员角色。

## 4. 基础资料维护

### 公司

后台「基础管理 → 公司」。

| 字段 | 说明 |
|---|---|
| 公司代码 | 用在导出文件名和邮件附件名上（如 `sales-report-A.xlsx`），**建后不要改** |
| 公司名称 | 登录页下拉和邮件标题里显示 |
| 排序 | 数字越小越靠前；登录页默认选中最靠前的 |
| 启用 | 停用后不再出现在登录页，历史数据保留 |

### 月度汇率

前台「汇率」页面，**按当前登录公司维护**。只需选择年月（如 2026-08），填 1 美元兑多少人民币；系统内部按当月 1 日存储。

- 外销、国外采购录入时会取当月汇率生成**快照**存进日报；之后改汇率不影响已保存的记录。
- 缺当月汇率时，录入会提示「XX公司缺少 YYYY年MM月 的美元兑人民币汇率」，而不是报错崩溃。
- 销售历史导入的 Excel 带「汇率」工作表，会一并写入当前公司。采购导入没有汇率表，**必须先手工维护**。

### 客户与供应商

后台可单条维护，前台有批量导入。名称在**同一公司内**唯一。停用后保留历史数据，但不再出现在新增日报的候选里。

## 5. 历史数据导入

所有导入都遵循 **下载模板 → 填写 → 预览 → 正式导入**，且写入**当前登录公司**。支持 `.xls` 和 `.xlsx`。

| 导入 | 入口 | 工作表 / 字段 |
|---|---|---|
| 客户 | `/core/customers/imports/` | 客户名称（兼容「名称」） |
| 供应商 | `/core/suppliers/imports/` | 供应商名称（兼容「供应商」「名称」） |
| 用户 | `/core/users/imports/` | 用户名、姓名、角色、初始密码（角色可写多个，用「、」或逗号分隔） |
| 销售历史 | `/sales/imports/` | 「数据表」：客户名称、业务跟单、销售类型、出货日期、数量、金额<br>「汇率」：日期、汇率 |
| 采购历史 | `/purchase/imports/` | 供应商、采购员、采购类型、采购日期、数量、金额（兼容销售样表列名） |

每个页面都有「下载导入模板」，模板含表头、两行示例和独立的「填写说明」工作表。

### 导入行为要点

- **预览只校验不写库**，逐行报出错误的行号和字段；有任何错误都不允许提交。
- **会自动建账号并授权**：「业务跟单」「采购员」列里的用户名若不存在会自动创建、加对应角色、并授予当前公司权限；若是另一家公司的已有账号，那个人就同时获得了这家公司的访问权限。**导入前务必核对名单。**
- 客户/供应商会自动在当前公司下建档并建立归属关系。
- 同名客户/供应商不重复创建；已存在的用户名不会被覆盖（预览时报错）。
- 全程写操作日志，每行记录来源文件和来源行号，可在后台「操作日志」回溯。
- 模板里的示例行会被当成真实数据校验，**正式导入前请替换或删除**。

### 导出

销售/采购报表页面的「导出 Excel」，导出当前公司 + 当前筛选条件下的明细，文件名带公司代码。

## 6. 邮件推送（阿里云企业邮箱）

### 配置发信参数

编辑服务器上的 `~/deploy/daily-report/.env`：

```
EMAIL_HOST=smtp.qiye.aliyun.com
EMAIL_PORT=465
EMAIL_USE_SSL=True
EMAIL_USE_TLS=False
EMAIL_HOST_USER=report@yourdomain.com
EMAIL_HOST_PASSWORD=邮箱密码或客户端专用密码
DEFAULT_FROM_EMAIL=report@yourdomain.com
```

> **阿里云硬性要求**：`EMAIL_HOST_USER` 与 `DEFAULT_FROM_EMAIL` 必须是**同一个已开通 SMTP 的地址**，否则发信被拒。
> 465 走 SSL；若内网只放通 587，改成 `EMAIL_PORT=587`、`EMAIL_USE_SSL=False`、`EMAIL_USE_TLS=True`。个人版邮箱主机名是 `smtp.aliyun.com`。

改完 `.env` 需重启容器生效：

```bash
ssh mesdevserver "docker restart daily-report-web daily-report-mailer"
```

### 配置收件组

前台「邮件推送」→「新增收件组」，**按公司分别建**（一个收件组只发本公司数据）：

| 字段 | 说明 |
|---|---|
| 收件组名称 | 同一公司内不能重名 |
| 推送内容 | 销售和采购 / 仅销售 / 仅采购 |
| 收件人 | 多个邮箱用英文逗号或换行分隔 |
| 抄送 | 可留空 |
| 每日发送时间 | 到点后由定时任务发送 |
| 附带 Excel 明细 | 勾选后附当日明细工作簿 |

页面上的「立即发送」按钮走与定时任务**完全相同**的发送路径，可用于试发。

### 邮件内容

标题 `[公司名] YYYY-MM-DD 经营日报`；正文含当日/本月累计/本年累计三档汇总（人民币、美元原币、折算人民币合计分列）和当日明细表格；附件是当日明细 Excel（销售、采购分两个工作表）。

**当天没有任何数据时默认跳过不发。** 同一收件组同一天成功发送后不会重复发送。

### 手工发送与排查

```bash
ssh mesdevserver "docker exec daily-report-web python manage.py send_daily_report <参数>"
```

| 参数 | 作用 |
|---|---|
| `--dry-run` | 只打印将要发送的收件组，不实际发信 |
| `--now` | 忽略收件组的发送时间，立即发送 |
| `--company A` | 只发指定公司代码 |
| `--list-id 3` | 只发指定收件组编号（补发用） |
| `--date 2026-08-20` | 指定业务日期 |
| `--force` | 当天已成功发送过也重新发送；也会绕过失败次数上限 |
| `--allow-empty` | 当天没数据也照常发送 |

排查顺序：① 后台「邮件发送记录」看有无失败记录及原因 → ② `--dry-run --now` 确认收件组被选中 → ③ 看 `logs/mail.log` 或 mailer 容器日志（见 §8）。

**失败次数上限**：同一收件组同一天失败 5 次后就不再自动重试了，命令输出里会打「已放弃」。这是为了避免 SMTP 故障时每 10 分钟重试一次、一天试 144 次，每次都重建报表还各阻塞 30 秒。修好问题后用 `--force` 补发：

```bash
docker compose exec web python manage.py send_daily_report --force --list-id 3
```

## 7. 部署与更新

### 一键部署 / 更新

在本地项目根目录执行：

```bash
bash scripts/deploy_remote.sh mesdevserver 8001
```

脚本做的事：传源码（**不传 `data/`**，不会覆盖服务器数据库）→ 生成 `.env`（已存在则保留）→ `docker build` → 重建两个容器 → 健康检查。重复执行即为更新，**数据不丢**。

容器启动时自动执行 `migrate`，无需手工迁移。

### 首次创建管理员

```bash
ssh mesdevserver "docker exec -it daily-report-web python manage.py createsuperuser"
```

创建后记得在后台给他授权公司，否则登录时选不到任何公司。

### 手工操作容器

```bash
ssh mesdevserver "docker restart daily-report-web"     # 重启
ssh mesdevserver "docker stop daily-report-web daily-report-mailer"   # 停止
ssh mesdevserver "docker exec -it daily-report-web python manage.py shell"  # Django shell
```

### 环境变量说明

| 变量 | 说明 |
|---|---|
| `DJANGO_SECRET_KEY` | 会话签名密钥，部署脚本自动生成，**不要泄露也不要随意更换**（换了所有人被登出） |
| `DJANGO_ALLOWED_HOSTS` | 允许的访问域名/IP，逗号分隔 |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | **通过 IP 或域名访问时必填**，含协议和端口，否则登录等 POST 被 CSRF 拦下 |
| `DJANGO_DEBUG` | 生产必须 `False` |
| `BACKUP_DIRECTORY` | 容器内备份目录，默认 `/app/backups` |

## 8. 备份与恢复

### 备份

备份是**自动的**：`backup` 容器每 24 小时备一次，保留最近 30 份，日志写 `logs/backup.log`。不需要再手工配 cron。

想立刻备一份：

```bash
ssh mesdevserver "docker exec daily-report-web python scripts/backup_sqlite.py"
```

不带参数就落到 `BACKUP_DIRECTORY`（宿主机 `~/deploy/daily-report/backups/`）。用的是 SQLite 在线备份 API，不直接复制正在使用的库文件，运行中执行也安全；备份完会跑 `PRAGMA integrity_check`，校验不过就非零退出。

**仍需人工做的一件事**：定期把 `backups/` 拷到另一台机器。备份和数据库在同一块盘上，磁盘坏了两者一起没。

检查备份是否正常：

```bash
ssh mesdevserver "ls -lh ~/deploy/daily-report/backups/ | tail -5"
ssh mesdevserver "tail -20 ~/deploy/daily-report/logs/backup.log"
```

### 恢复

1. 停容器：`docker stop daily-report-web daily-report-mailer`
2. **先把当前库另存一份**（万一恢复的不是想要的版本）
3. 把备份文件复制成 `data/daily_report.sqlite3`
4. 修权限：`sudo chown 10001:10001 data/daily_report.sqlite3`
5. 起容器：`docker start daily-report-web daily-report-mailer`
6. 验证：`docker exec daily-report-web python manage.py check`

## 9. 日志与排错

### 看日志

```bash
ssh mesdevserver "docker logs --tail 100 daily-report-web"
ssh mesdevserver "docker logs --tail 100 daily-report-mailer"
```

### 操作日志

后台「操作日志」记录了所有新增/修改/删除/导入/重置密码，含操作人、时间、变更前后的字段值（中文字段名），可追溯到具体数据编号。

### 常见故障

| 现象 | 原因与处理 |
|---|---|
| 登录页能打开，但登录点不动/报 CSRF 403 | `.env` 里 `DJANGO_CSRF_TRUSTED_ORIGINS` 没配或不含当前访问的 `协议://IP:端口`。补上后重启容器 |
| `attempt to write a readonly database` | 挂载目录权限不对（容器内以 uid 10001 运行）。`sudo chown -R 10001:10001 ~/deploy/daily-report/data` |
| 容器反复重启，日志有 `NumPy was built with baseline optimizations (X86_V2)` | 这台服务器 CPU 是 Core2 Duo，不支持 x86-64-v2。`requirements.txt` 已锁 `numpy==1.26.4`，**不要升级 numpy 到 2.x** |
| 用户登录后提示「没有可进入的公司」 | 该账号没有任何公司授权，在后台「用户公司授权」添加 |
| 录入外销提示缺少汇率 | 该公司该月份汇率未维护。汇率按公司分开，另一家有不算 |
| 邮件没发出 | 见 §6 排查顺序 |
| 报表页数字和预期不符 | 先确认导航栏「当前公司」；再确认「人民币/美元」是原币合计不能相加，总额看「折算人民币」 |

### 安全说明

当前是内网 HTTP 部署，未启用 HTTPS。`python manage.py check --deploy` 会报 5 条 HTTPS/密钥相关警告，属于内网部署的已知取舍。若将来对外暴露，需前置 nginx 做 TLS，并补 `SECURE_SSL_REDIRECT`、`SESSION_COOKIE_SECURE`、`CSRF_COOKIE_SECURE`。

## 10. 附：数据模型速查

| 模型 | 表意 | 是否按公司隔离 |
|---|---|---|
| `Company` | 公司 | — |
| `CompanyMembership` | 用户可进入哪些公司 | — |
| `Customer` / `Supplier` | 客户 / 供应商 | ✅（公司内名称唯一） |
| `ExchangeRate` | 月度汇率 | ✅（公司+月份唯一） |
| `SalesShipment` | 销售日报 | ✅ |
| `PurchaseReceipt` | 采购日报 | ✅ |
| `SalesAssignment` / `PurchaseAssignment` | 客户/供应商归属人 | 间接（随客户/供应商所属公司） |
| `MailingList` | 邮件收件组 | ✅ |
| `DeliveryLog` | 邮件发送记录 | 间接（随收件组） |
| `OperationLog` | 操作日志 | 全局（含公司字段快照） |
| `UserProfile` | 是否需强制改密 | 全局 |
