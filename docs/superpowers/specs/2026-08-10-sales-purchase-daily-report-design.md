# 销售采购轻量日报系统设计规格

## 1. 目标与边界

在公司内网部署一个浏览器访问的日报系统，同时支持销售出货和采购业务。系统替代多人维护 Excel 的日报过程，提供账号登录、按本人业务范围填写明细、历史数据导入和可筛选的图表报表。

销售与采购共用账号、权限、汇率、操作日志和报表基础能力，但属于两个独立领域：数据表、录入页面、导入模板、接口和统计口径均独立维护。首期不实现订单、产品、库存、毛利、付款、收款或 ERP/MES 自动同步；这些数据在现有出货表中没有足够字段支撑。

## 2. 已确认的业务规则

- 部署范围：公司内网。
- 登录方式：系统自建账号和密码。
- 销售日报：销售负责人填写本人客户的出货明细。
- 采购日报：采购员填写本人供应商的采购明细。
- 审批：不设审批流程。保存后立即计入统计；管理员可更正所有记录。
- 历史数据：销售与采购同步上线。销售导入现有 `.xls` 中的全部 4,207 条明细；采购历史明细必须在正式迁移前提供，并按同一质量控制规则导入。
- 金额：内销和国内采购以人民币录入；外销和国外采购以美元录入。系统同时保存原币金额、当月汇率快照和折算人民币金额。
- 采购模型：按用户授权，采购按销售的日报结构推导。后续收到采购源表时，只调整采购字段映射和导入校验，不改变销售模块。

## 3. 用户、角色和数据范围

| 角色 | 权限 |
| --- | --- |
| 管理员 | 管理用户、客户、供应商、归属关系和汇率；导入历史数据；查看和更正全部记录；查看全部报表。 |
| 销售人员 | 新增、修改、删除和查看本人客户的销售明细；查看本人销售报表。 |
| 采购人员 | 新增、修改、删除和查看本人供应商的采购明细；查看本人采购报表。 |
| 报表查看者 | 只读查看被授权范围的报表，不可访问或修改明细。 |

一个账号可同时拥有销售和采购人员角色。销售人员不能查看其他销售人员的数据；采购人员不能查看其他采购人员的数据。管理员和报表查看者的可见范围由管理员配置。

## 4. 功能设计

### 4.1 共享平台

- 登录、退出、修改本人密码、管理员重置密码。
- 用户、角色、客户、供应商、客户归属、供应商归属和月度汇率维护。
- 全局操作日志，记录新增、修改、删除、导入和管理员更正的操作人、时间、对象和变更前后值。
- Excel 导入预览、错误行下载和结果确认；Excel 导出使用当前筛选条件。

### 4.2 销售模块

销售明细至少包含：客户、业务跟单、销售类型、出货日期、数量、币种、原币金额、汇率快照、折算人民币金额、来源和操作时间。

销售类型为内销或外销。内销固定人民币，外销固定美元；用户选择日期后，系统读取该月汇率，计算并保存折算人民币金额。客户下拉列表仅显示当前销售人员被分配的客户。

### 4.3 采购模块

采购明细至少包含：供应商、采购员、采购类型、采购日期、数量、币种、原币金额、汇率快照、折算人民币金额、来源和操作时间。

采购类型为国内采购或国外采购。国内采购固定人民币，国外采购固定美元；字段行为与销售模块一致。供应商下拉列表仅显示当前采购员被分配的供应商。

采购模块不复用销售 API 或销售数据表。采购明细新增字段时，仅扩展采购表和 `/api/purchase/**` 接口。

### 4.4 报表与图表

销售与采购分别提供以下报表，并共享日期、人员、往来单位和业务类型筛选方式：

- 日报：当日数量、人民币金额、美元金额和折算人民币总额。
- 月累计和年累计：数量、原币金额和折算人民币金额。
- 趋势：按日和按月的数量、折算人民币金额，支持与上一年度同期间比较。
- 结构：内销/外销、国内采购/国外采购的数量和金额占比。
- 排行：按负责人/采购员、客户/供应商的数量和金额排行。

首期销售与采购仅并列展示汇总指标，不计算毛利、库存或业务单据之间的关联。

## 5. 数据模型和接口边界

共享表包括 `users`、`roles`、`user_roles`、`customers`、`suppliers`、`sales_assignments`、`purchase_assignments`、`exchange_rates` 和 `operation_logs`。

销售表为 `sales_shipments`，采购表为 `purchase_receipts`。两表分别保存业务主键、往来单位主键、责任人、业务类型、日期、数量、币种、原币金额、汇率快照、人民币折算金额、来源、创建和更新时间。汇率快照不可因后来修改月度汇率而改变。

接口按领域划分：

- `/api/auth/**`：登录、密码和会话。
- `/api/admin/**`：用户、权限、基础资料、归属关系、汇率和操作日志。
- `/api/sales/**`：销售明细、销售导入和销售报表。
- `/api/purchase/**`：采购明细、采购导入和采购报表。
- `/api/reports/**`：只读聚合与导出。

任何销售导入、采购导入或未来 ERP/MES 同步均通过各自领域接口写入；公共接口不接受混合业务明细。

## 6. 历史数据迁移与质量控制

销售源文件 `出货明细(26.7.7）.xls` 的 `数据表` 已识别出客户名称、业务跟单、销售类型、出货日期、数量和金额六个有效字段，覆盖 2024-12-02 至 2026-08-10。迁移时导入 4,207 条明细、116 个客户、7 位负责人、基础信息和汇率表。

迁移分为解析校验、预览对账和正式写入三个步骤。正式写入前必须完成以下核对：记录数等于 4,207；按月、销售类型汇总的数量和金额与原 Excel 一致；客户、负责人和日期均不为空。

源 Excel 没有出库单号，同日期、同客户、同数量和同金额的重复行可能是不同的真实业务。迁移不得自动删除此类记录；每个来源行保留导入批次和行号。采购数据遵循相同迁移策略。

## 7. 技术与部署

采用单体内网 Web 应用：Django 5 负责页面、账号、权限、后台管理和业务接口；HTMX 用于局部页面交互；ECharts 用于图表；SQLite 用于数据存储。Excel 导入使用 `pandas` 和 `xlrd` 读取 `.xls`，Excel 导出使用 `openpyxl`。该方案不需要 Java、Node.js 构建链或独立数据库服务。

系统以一个 Python 服务和一个 SQLite 数据库文件部署在公司内网服务器，浏览器通过内网地址访问。Windows 环境使用 Waitress 运行，并注册为系统服务；Linux 环境使用 Gunicorn。建议服务器配置至少为 2 核 CPU、4 GB 内存和 30 GB 磁盘。

SQLite 必须启用 WAL 模式和写入等待超时，以支持多位人员短时并发保存日报。每日通过 SQLite 在线备份机制生成备份文件并复制至公司受控存储，不直接复制正在使用的数据库文件。管理员密码使用 Django 的不可逆哈希保存。

当系统出现 20 位以上高频并发填报、持续的自动数据同步，或 SQLite 写入等待成为实际瓶颈时，迁移至 MySQL。销售、采购的数据表和接口边界不变，仅替换 Django 数据库配置并执行迁移。

## 8. 验收标准

- 销售和采购人员只能查看和修改本人被授权的往来单位明细。
- 管理员可完成用户、归属关系和汇率维护，并可查看操作日志。
- 内销/国内采购使用人民币，外销/国外采购使用美元；报表显示原币与按记录快照折算的人民币金额。
- 销售历史迁移记录数和月度汇总与原 Excel 对账一致。
- 销售和采购录入、导入、查询、导出和报表之间不存在数据串域。
- 日报、累计、趋势、结构和排行报表可按权限和筛选条件正确返回数据。

## 9. 实施节奏

在 1 名开发人员和业务方及时确认导入结果的前提下，预估 12 至 16 个工作日：先完成基础平台和数据模型，再完成销售模块、采购模块、历史迁移与报表，最后进行权限、迁移和用户验收。
